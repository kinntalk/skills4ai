- **HIGH（高）**: 应尽快修复的重要安全问题或质量问题
- **MEDIUM（中）**: 应该修复的中等问题
- **LOW（低）**: 建议改进的低优先级问题

## 最佳实践建议

### 安全性最佳实践

1. **避免动态代码执行**
   - 不要使用 eval()、exec() 或 compile() 处理用户输入
   - 使用白名单验证用户输入
   - 限制文件系统访问范围

2. **安全的文件操作**
   - 始终使用 pathlib.Path() 而非字符串拼接
   - 使用显式编码（encoding='utf-8'）
   - 验证文件路径，防止路径遍历攻击

3. **安全的子进程调用**
   - 避免使用 shell=True
   - 使用列表参数而非字符串
   - 验证所有命令参数

4. **输入验证**
   - 始终验证和清理用户输入
   - 使用类型检查和边界验证
   - 避免直接使用用户输入

5. **敏感数据保护**
   - 不要在日志中记录敏感数据
   - 使用环境变量存储凭据
   - 实施数据脱敏

### 规范性最佳实践

1. **错误处理**
   - 使用特定的异常类型
   - 避免裸 except 子句
   - 提供有意义的错误消息
   - 适当传播异常

2. **日志记录**
   - 使用适当的日志级别
   - 结构化日志消息
   - 避免在日志中记录敏感信息
   - 使用日志模块而非 print 语句

3. **代码组织**
   - 保持函数简短（<50 行）
   - 减少嵌套深度（<4 层）
   - 避免代码重复
   - 使用有意义的变量和函数名

4. **文档**
   - 为所有函数提供文档字符串
   - 包含使用示例
   - 说明参数和返回值
   - 记录已知限制

### 输出质量最佳实践

1. **Token 优化**
   - 避免冗长的注释和文档
   - 使用简洁的指令
   - 避免重复代码
   - 优化算法复杂度

2. **AI 交互**
   - 提供清晰简洁的指令
   - 避免冗长的输出
   - 使用结构化输出格式
   - 最小化不必要的解释

3. **输出管理**
   - 限制调试输出
   - 使用适当的日志级别
   - 避免过多的 print 语句
   - 整合相关输出
